### #02. Deepen the Compositor Engine to Stop Per-Frame Re-Reconciliation & Full-Res Blur

- **Strength**: `Strong` · **Dependency Category**: `in-process`
- **Exact Files, Symbols & Line Numbers**:
  - `shared/remotion/src/Composition.tsx`: root `useCurrentFrame()` in `YonruClip` (L261), per-frame `console.log('[Remotion Render] Props:', ...)` during `isRendering` (L351–360), 30-frame `console.log` computing `framingIndex.computeFraming(...)` (L432–437), per-frame `timelineTextItems.filter(...)` (L363–366), inline `renderMediaViewports` closure (L511–568), `<TimelineFrameRetention>` render-prop (L576–640), `premountFor` (L601–612), `HeadlessMediaViewports` mounting duplicate `<OffthreadVideo>` for Landscape Blur (L75–118 + L133–151) and **Stacked Multi-Speaker Reframe** (L133–186)
  - `shared/remotion/src/CanvasVideoCompositor.tsx`: `useCurrentFrame()` (L93), `useLayoutEffect` / `useEffect` (L427–455, L510–542), full-resolution `1080×1920` `ctx.filter = 'blur(...)'` per frame (L246–259), `draw()` missing an early-return after priming 1 frame when `!isActiveRef.current` (L181–364)
  - `shared/remotion/src/TimelineFrameRetention.tsx`: `handleFrameRendered` blitting full `1080×1920` `retentionCanvas` on every frame whenever `windows.length > 1` (L151–170)
  - `shared/remotion/src/AnimatedSubtitles.tsx`: wall-clock CSS `transition: 'all 0.1s'` / `'all 0.1s ease'` (L230, L466)
- **Verified Mechanism & Measurements**:
  1. Root `useCurrentFrame()` forces React to re-run the entire 843-line `YonruClip` module on every frame in Preview and Export, even while `CanvasVideoCompositor` already draws via `requestVideoFrameCallback`.
  2. `isRendering` logs `[Remotion Render] Props:` on every frame (~1,800 Puppeteer CDP `Runtime.consoleAPICalled` IPC round-trips for a 60s 30fps export).
  3. **Landscape Background Treatment (`blur`)** executes a 2D-canvas Gaussian blur directly on a `1080×1920` (2.07 MP) canvas with 1.08× overscan every frame; a `1/8`-scale (`135×240`) cached offscreen canvas reduces blur pixels by **~64×**.
  4. When a clip has `>1` **Timeline Video Segment**, `TimelineFrameRetention` copies a full 2.07 MP frame on every single playback tick instead of only near cut points/pause, while premounted segments run two `1080×1920` `CanvasVideoCompositor` draws concurrently during the 1.5s `premountFor` overlap.
  5. CSS `transition: 'all 0.1s'` in `AnimatedSubtitles.tsx` uses wall-clock time during multi-tab headless rendering, risking frame nondeterminism.
- **Deepening Direction**:
  - Push `useCurrentFrame()` into narrow leaf modules (`AdaptiveSubtitle`, `ActiveTextOverlay`, `HeadlessMediaViewports`), eliminate the `TimelineFrameRetention` render-prop, downscale **Landscape Background Treatment** blur onto a cached offscreen canvas, snapshot retention frames only near segment cut points/pause, gate premounted `CanvasVideoCompositor` instances to 1 primed frame until active, and remove per-frame `console.log` and CSS `transition`s. Keep `YonruClipProps` intact.
- **Relevant ADRs & Test Gaps**:
  - **ADRs**: Strengthens **ADR-0015** (**Compositor Engine**), **ADR-0028**, and **ADR-0031** with zero visual-parity or prop-contract changes.
  - **Test Gaps**: Add regression assertions in `shared/remotion` Vitest suites for premount single-frame gating, blur scratch canvas, and zero per-frame console output.

### #03. Deepen Headless Render Subprocess Ownership, Cancellation Teardown & GPU Encoding

- **Strength**: `Strong` · **Dependency Category**: `local-substitutable`
- **Exact Files, Symbols & Line Numbers**:
  - `backend/core/render_engine.py`: `RenderPipelineCoordinator.__init__` duplicating FFmpeg PATH probing and mutating global `os.environ["PATH"]` (L899–923), `_build_remotion_cmd` (L1069–1090), `render_streaming` spawning `subprocess.Popen` inside `with self._stage_render_context(...)` with blocking `process.stdout.readline()` and no `try/finally` process-tree kill on `GeneratorExit` (L1123–1198), `StagedRenderContext._cleanup` (L444–460)
  - `backend/main.py`: `render_clip_stream` (`POST /api/render-stream`, `render_activity_tracker.track()`, L472–488)
  - `frontend/app/composables/useClipperExport.ts`: `cancelRender()` calling `activeAbortController.abort()` (L158–225)
  - `shared/remotion/remotion.config.ts`: only sets `videoImageFormat('jpeg')` and `overwriteOutput(true)` (L1–4)
  - Verified Remotion internals: `shared/remotion/node_modules/@remotion/renderer/dist/render-media.js:680` (`hardwareAcceleration` defaults to `'disable'`) and `probe-encoder.js:56–99` (`--hardware-acceleration=if-possible` auto-probes `h264_videotoolbox` / `h264_nvenc` with `libx264` fallback); `.bundle/` is `28 MB` (>14 MB `.js.map` source maps).
- **Verified Mechanism & Measurements**:
  1. Aborting an export SSE stream closes `sse_generator()` and raises `GeneratorExit` (`BaseException`), bypassing `except Exception` in `render_streaming`. `StagedRenderContext.__exit__` immediately deletes `source_*.mp4`, `cover_*.jpg`, `audio_*.mp3`, and `props_*.json` while the orphaned `remotion render` + Chrome Headless Shell + FFmpeg process tree continues burning CPU/RAM.
  2. `render_activity_tracker.track()` decrements `active_count` to `0` while the orphaned process tree is still running, violating `SelfUpdateService.preflight()`'s active-render check.
  3. `_build_remotion_cmd` omits `--hardware-acceleration`, forcing software `libx264` even on Apple Silicon or NVIDIA hosts, and ignores **Hardware Capability Profile** RAM limits.
  4. Inline `subprocess.run`/`subprocess.Popen` calls force `backend/tests/test_render_engine.py` to monkeypatch `subprocess` and leave cancellation teardown untested.
- **Deepening Direction**:
  - Introduce a two-adapter `RemotionProcessAdapter` seam (`SubprocessRemotionAdapter` + `FakeRemotionAdapter`) owning process-group spawning (`start_new_session=True` / `CREATE_NEW_PROCESS_GROUP`) and guaranteed `try/finally` tree termination (`SIGTERM`→`SIGKILL` / `taskkill /F /T`) **before** `StagedRenderContext` removes staged assets, plus disconnect-aware stream polling.
  - Enable `--hardware-acceleration=if-possible` with **Hardware Capability Profile**-bounded concurrency, and delegate FFmpeg availability checks to **Media Transcoder Engine**.
- **Relevant ADRs & Test Gaps**:
  - **ADRs**: Repairs an active breach of **ADR-0032** (`RenderActivityTracker` idle-render invariant) and extends **ADR-0011**.
  - **Test Gaps**: `backend/tests/test_render_engine.py` has zero tests for `gen.close()` / `GeneratorExit` subprocess teardown before staging cleanup or hardware-acceleration CLI flag generation.

### #04. Consolidate Triple-Pass Ready Clip Extraction & Single-Flight Face Tracking Behind Media Transcoder Engine

- **Strength**: `Strong` · **Dependency Category**: `local-substitutable`
- **Exact Files, Symbols & Line Numbers**:
  - `backend/core/clip_session_store.py`: `create_clip` running raw FFmpeg (L669–762; L728–740) and secondary screenshot (L743), `extract_clip_audio` running raw FFmpeg (L764–791; L783–790), mutable `_run_ffmpeg` bypass property (L828–834), `ensure_crop_map` whose `_face_tracker_lock` only guards `FaceTracker` creation, not per-clip execution (L592–645; L614–618)
  - `backend/core/media_transcoder.py`: `slice_video` (L357–389 — 0 prod callers), `extract_audio` (L391–415 — 0 prod callers), `extract_frame` (L311–345)
  - `backend/core/workflow_coordinator.py`: `run_local_cut` (L826, L876–890)
- **Verified Mechanism & Measurements**:
  1. Provisioning a **Ready Clip** executes 3 sequential FFmpeg processes plus 1 `ffprobe`: (1) cut & re-encode `video.mp4` (`libx264` + `aac`), (2) `ffprobe` duration on `video.mp4` + FFmpeg #2 for frame-0 **Clip Thumbnail** (`thumbnail.jpg`), and (3) FFmpeg #3 decoding the just-encoded AAC audio back to 16kHz mono PCM `audio_v2.wav`.
  2. `audio_v2.wav` has zero consumers after Whisper finishes yet persists on disk (`31.08 MB` across 28 workspace clips).
  3. `MediaTranscoder.slice_video` and `extract_audio` have zero production callers because `ClipSessionStore` duplicates FFmpeg commands inline and mutates `self.transcoder.run_ffmpeg` via `_run_ffmpeg`.
  4. Concurrent `ensure_crop_map(folder_name, clip_id)` calls before `crop_map.json` exists both miss `get_crop_map()` and decode the 1080p clip twice in parallel while contending on `MediaPipeFaceDetector._lock`.
- **Deepening Direction**:
  - Deepen **Media Transcoder Engine** with a multi-output extraction interface emitting `video.mp4`, frame-0 **Clip Thumbnail**, and 16kHz PCM audio in a single decode pass from `full.mp4`, removing the raw `_run_ffmpeg` bypass in **Clip Session Store** and letting Whisper start immediately in ADR-0033's executor.
  - Add a per-`(folder_name, clip_id)` single-flight lock inside `ClipSessionStore.ensure_crop_map` (matching `AssetRepository._download_locks`).
- **Relevant ADRs & Test Gaps**:
  - **ADRs**: Builds on **ADR-0033** while preserving **ADR-0008** and **ADR-0022** (`thumbnail.jpg` at `00:00:00`).
  - **Test Gaps**: Update `test_clip_session_store.py` (which currently monkeypatches `_run_ffmpeg`) to cross the `MediaProcessAdapter` seam; add concurrency test for single-flight `ensure_crop_map`.

### #05. Persist Probed Media Specs & Batch-Extract Hook Thumbnails in Asset Repository and Hook Discovery Engine

- **Strength**: `Strong` · **Dependency Category**: `local-substitutable`

  - `backend/core/hook_discovery_engine.py`: `load_cached_hooks` calling `sanitize_and_prepare_hooks` unconditionally (L162–176), `get_or_discover_hooks` (L286–323), sequential `capture_screenshot` loop (L325–370; L360–364)
  - `backend/core/media_transcoder.py`: single-frame-only `extract_frame` / `capture_screenshot` (L311–355)
  - `backend/core/workflow_coordinator.py`: `load_ready_clip` (L528) and `replay_cached_analysis` (L216)
  - `backend/main.py`: `GET /api/cached` (L493–508)
  - Hot frontend caller: `frontend/app/composables/useCommandPalette.ts` (`GET /api/cached?limit=100`, L56–68)
- **Verified Mechanism & Measurements**:
  1. On a cold server restart (`MediaTranscoder._probe_cache` empty), opening the **Command Palette** (`GET /api/cached?limit=100`) invokes `_hydrate_cached_video_list_item` sequentially across all cached sources. Measured on this host: `644.5ms` for 5 real `full.mp4` files (`128.9ms/video`), extrapolating to **`~4.25s`** for the workspace's **33 cached videos** (compared to `5.60ms` total to read all 34 `metadata.json` files).
  2. Real workspace **Source Videos** contain **12–23 Hooks**, and **13 of 35 cached sources currently have `hooks > thumb_*.jpg`**. Calling `load_cached_hooks` synchronously during `POST /api/load-ready-clip` spawns 13–23 sequential `ffmpeg` frame seeks, blocking the **Editor Transition Overlay**.
  3. `AssetStore.sanitize_and_prepare_hooks` and `AssetRepository.extract_clip_screenshot` fail the deletion test (constructing throwaway `HookDiscoveryEngine` / `ClipSessionStore` instances per call).
- **Deepening Direction**:
  - Persist fingerprinted `MediaSpecs` (`duration`, `width`, `height`, `fps`, source size/mtime) inside `metadata.json` behind an mtime-indexed **Asset Repository** catalog (`video_id` O(1) lookup + cached listing), route `_generate_thumbnail` through `MediaTranscoder.extract_frame`, and delete the two dead pass-through wrappers.
  - Deepen **Media Transcoder Engine** with bounded parallel batch frame extraction, and separate read-only `load_cached_hooks` from explicit/background **Hook** thumbnail backfill.
- **Relevant ADRs & Test Gaps**:
  - **ADRs**: Extends `0a9b5b1` across server restarts; aligns with **GLOSSARY.md**.
  - **Test Gaps**: Add `FakeMediaAdapter` assertions confirming zero `ffprobe_info` calls on warm `metadata.json` hits and single-probe parallel batching in `extract_frames`.
